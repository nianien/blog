# 审阅文章

先读取项目根目录 `AGENTS.md`，通读全文与有关参考材料。沿用用户已经明确的目的、读者、版本和范围。内容标准以第 3 节为准，行文与去 AI 味标准以第 9 节为准，技术与页面证据按有关章节核验。

先判断文章想说明什么、能否成立和读者能否跟上，再审阅局部措辞与格式。不要让大量轻微风格意见淹没核心问题。

## 审阅维度

| 维度 | 判断依据 |
| --- | --- |
| 主线与类型 | 观点文是否有明确判断，教程是否完成任务，排障记录是否有证据链；标题与开篇的承诺是否兑现，主要篇幅是否服务主线 |
| 论证与技术深度 | 按文章类型检查机制解释、操作前提或排障推理；是否跳步、循环论证或将相关性当作因果 |
| 事实与证据 | 实现、版本、参数、数据与主张是否对应，推测与演示是否冒充实测，需核查的外部主张与引文是否就近标注来源 |
| 结构与衔接 | 章节顺序是否符合理解依赖，各节是否推进问题，段落是否突兀或重复 |
| 全文自洽 | 术语、假设、时间、口径、案例和结果是否一致，后文是否悄悄扩大结论范围 |
| 案例与配图 | 场景是否连贯，文字、代码、节点、箭头、截图版本与测试结果是否对应 |
| 前瞻判断 | 是否从有依据的变化推导影响，是否交代条件与可观察信号，是否把计划写成事实 |
| 价值与表达 | 是否讲清实际收益，句子是否顺畅，是否用空泛赞词、机械结构或重复总结替代内容 |
| 格式与页面 | 按审阅范围检查 YAML、资源、路由、代码块及目标渠道的实际渲染 |

- 宣传文章突出真实价值，不因缺少缺点专章、替代方案排行或未来预测而扣分；影响主张成立的前提需准确简洁
- 没有独立展望章节不等于缺少前瞻性；评价文中实际提出的延伸判断，不强行替作者添加预测
- 评测和选型文章按用户要求核对比较维度与条件，不能把特定场景的结果泛化
- 代码、图片或测试证据未读到时，将对应判断列为待核验，不根据图名或类名猜实现
- 指出“AI 味”时定位到句段及其问题，例如没有信息增量、因果不成立、句式重复；不以检测分数、禁词命中数或笼统印象代替编辑判断
- 按 AGENTS.md 第 1 节区分硬要求、质量目标与默认建议；不把字数、标签数或视觉偏好作为必须修正项
- 按第 8 节选择验证范围与渠道；局部文字审阅不自动增加全站构建或微信验收
- 规则引擎主题涉及实现、演示或压测时，按需读取 [专项核验](../write-article/references/rule-engine.md)
- 审阅范围包含配图时读取 `../svg-check/SKILL.md`；静态工具通过不能代替图意与浏览器检查
- 仅审阅时不修改正文；用户同时要求优化时，先修正主线与论证，再润色并复测，不擅自改变定位

## 报告

先给结论，再列少量有证据、可行动的问题。每项包含文件/位置、观察事实、对读者理解或结论的影响，以及具体改法；区分实质错误、证据不足与风格偏好。

| 等级 | 适用情形 |
| --- | --- |
| 必须修正 | 核心主线偏离、事实错误、核心论证断裂、图文冲突、误导性证据或主要内容无法阅读 |
| 建议优化 | 结构、衔接、密度、措辞或维护性可以改善，但核心判断仍成立 |
| 待核验 | 证据不足，说明需要什么证据，不当作已确认缺陷 |

说明覆盖了什么、未验证什么，列出值得保留的观点与表达。只在用户要求或比较多篇文章时给分，不用评分替代问题证据。内部审阅记录与对外正文分开。
