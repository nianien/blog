# 博客布局优化方案与审阅记录

## 目标与边界

保持自然写作、发布时间倒序和静态链接。页面不增加设计旁白、推荐、精选、自动选文、动态筛选或新宣传文案。保留文章内容、日期、分类、标签和已有路由。本次不提交、推送或发布。

## 第一版方案

- 首页、分类、标签与全部文章统一单列列表，标题、摘要、日期与分类按阅读顺序排列
- 顶部三个导航直接展示，手机也不使用全屏菜单
- 列表宽 860px，正文文字宽 800px，技术图表和代码可使用 1040px
- 首页保留现有标语和最近九篇；列表页有真实栏目标题、数量和静态分类链接
- 文章去外层大卡片、缩小手机标题，提供目录和已有系列入口
- 关于页整理信息层级，联系方式共用一份展示，补齐页面标题
- 统一浅色主题、焦点样式与链接样式

## 第一轮审阅：兼容性与范围

1. 若同时减少每页数量，会改变旧分页内容边界，并扩大 sitemap 与链接回归范围。修订：保留每页 18 篇，以紧凑列表和现有分页控制阅读，保留全部旧路由
2. 标签同义词合并是内容治理，可能影响文章归属和旧 URL。修订：本次不合并标签，不调整文章元数据
3. 不能统一将所有内容压到 800px，截图、宽表格和代码会明显缩小。修订：仅普通文字段落、列表和标题限宽，媒体与表格独立使用正文最大宽度
4. 关于页经历不能在排版任务中凭空补充或改变。修订：只整理既有内容顺序、增加必要栏目标题，去掉重复公司链条；联系方式以现有关于页为统一来源

## 第二轮审阅：阅读、语义与可实现性

1. 展开的长目录会挤占手机首屏。修订：使用浏览器原生 details 展示目录，默认折叠，目录链接在构建时生成，不引入滚动监听或选文逻辑
2. 修改公共 Markdown 转换可能影响微信。修订：目录仅在网站文章页面生成，保留已有 heading id，避免重复 id；网站与微信共用的路由和图片解析不变
3. 把三列改为单列后不能保留卡片式标签、按钮和大空白。修订：列表只显示完整标题、最多三行摘要、日期与分类，标题直接链接正文
4. 移动端分类不能横向隐藏选项。修订：采用自然换行的静态文字链接，减小间距，一级与子分类分别呈现；320px 下允许导航自然换行
5. 原有暗色模式只替换部分颜色会导致深底深字。修订：统一浅色 color-scheme，清理不完整的自动暗色样式，不增加主题切换开关
6. 不能为视觉美化取消可访问性。修订：h1/h2 层级、aria-current、键盘焦点、跳转正文链接、分页换行和文字对比度纳入验收

## 通过结论

上述修订后，方案满足自然排序、静态生成、路由兼容、正文与媒体分别控制宽度的约束，可以实施。所有解释与审阅记录只保存在本文件，不进入网站页面。
