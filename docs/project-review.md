# 工程架构、项目规范与 Skills 审阅

审阅日期：2026-09-16

## 结论

现有 Markdown + Next.js 静态输出架构适合个人技术博客，不需要为本次问题更换框架。优先需要优化的是规范的一致性、SVG 工具的可靠性，以及网站与微信两条内容链路的契约。

本次确认并修复了规则冲突、过时文档、SVG 零扫描误报、不安全自动改写和微信预览进入发布路径的问题。这些问题能够解释一部分错误来源，但不能据此断言历史上每次文章或 SVG 不准确都由同一原因造成。

## 审阅范围与架构

检查了内容加载与路由、分类与系列导航、文章页面和客户端高亮、SEO/RSS/sitemap、构建配置、统一 CLI、微信预览/转换/发布链路、SVG 审计/修复，以及公共规范和两套三个技能入口。

| 层次 | 当前实现 | 判断 |
| --- | --- | --- |
| 内容来源 | 本地 Markdown、gray-matter、图片目录 | 简单、可版本管理，适合当前规模 |
| 内容服务 | src/lib/blog.ts 读取、解析、过滤与导航 | 职责清晰，但列表元信息和正文转换耦合 |
| 页面输出 | Next.js App Router、静态参数、可选静态导出 | 无需架构迁移；需区分开发、生产服务和 out 静态预览 |
| 客户端增强 | 代码高亮、历史 Mermaid、Giscus | 功能独立，后续可改善 DOM/React 生命周期管理 |
| 微信输出 | 独立 marked renderer、sharp、云托管代理 | 有合理的渠道差异，但公共路由与资源契约应复用 |
| 代理执行 | AGENTS、CLAUDE、两套 skills | 原先重复且发生分歧，已整理为共享实现 |

## 本次已修复

### 1. 公共规范与技能存在相互冲突的要求

旧写作技能要求每步等待确认，公共执行要求明确任务直接执行；旧审阅技能要求补充局限与未来视角，容易改变已确认的宣传定位；字符扫描被当成硬判据，容易把格式通过误当成质量通过。

现在公共规范统一在 [AGENTS.md](../AGENTS.md)，[CLAUDE.md](../CLAUDE.md) 加载该文件。技能实现统一在 [.agents/skills](../.agents/skills/)，Claude 保留发现入口与脚本兼容入口。写作、审阅和图形检查分别承担不同职责，不重复维护格式大全。

新技能保留事实核验、命名一致、读者视角和图文检查，取消无依据的词频硬阈值、强制逐步确认、强制缺点专章与机械评分。

### 2. SVG 审计对单文件会“扫描 0 个，全部通过”

旧脚本只遍历目录。将具体 SVG 文件作为参数时，跳过文件后仍返回成功。本次在修改前实际复现。

现在支持明确文件、目录或图片目录名，目录递归扫描；空目标、缺失目标、无 SVG、无效 XML 或 viewBox 都不会作为成功返回。全库只读审计需要显式 --all，不再通过前缀猜测扩大检查范围。

静态输出说明覆盖边界，变换和复杂元素提示人工检查，不再宣称静态检查能证明视觉与语义准确。

### 3. SVG 自动修复会丢失箭头或样式

旧转换函数只识别部分 M/L 路径，却会移除无法转换的 marker 引用。本次用带 H 指令的路径复现了“原图有箭头、转换后无箭头”。其追加 polygon 到根节点的方式也会改变原分组变换与绘制层次。CSS 转换仅理解部分 class，却删除整个 style 块。

现在只自动修复基础属性；遇到 marker 或 CSS 时拒绝改写该文件，保留原内容并要求人工核对。增加 dry-run、无损拒绝与幂等性验证。修复器不会用删除图形语义的方式换取审计通过，也不再为统一描边而覆盖已有宽度。审计区分文件错误与样式、启发式几何提醒；后两者不直接导致非零退出码，需结合实际图形判断。

### 4. 微信预览之后仍然进入发布函数

[scripts/wx/publish.ts](../scripts/wx/publish.ts) 原先在预览异步分支之后无条件调用 publish，因此可能尝试上传素材和创建草稿。现在明确按模式隔离。用本地 stub 运行实际模式分支：预览写入本地输出，发布调用次数为零；发布模式只进入一次发布路径。

没有读取真实发布凭证、上传图片、创建公众号草稿或部署服务。

### 5. README 与实际工程不一致

旧文档引用不存在的 install.sh、restart.sh、deploy.sh，以及已经不存在的 DIR_TO_VIRTUAL 映射。微信配置文档要求 APPID/APPSECRET，实际客户端读取代理地址及 token。

[README.md](../README.md) 与 [scripts/README.md](../scripts/README.md) 已按实际代码重写，说明当前架构、命令、slug、分类、静态预览缓存及微信转换边界。Python 缓存已加入忽略规则。

### 6. 网站与微信的文章路由和图片解析不一致

现已提取 `src/lib/content-paths.ts`，网站正文和微信使用相同的本地资源解析；网站 canonical、RSS、sitemap 与微信原文链接使用相同路由规则。保留目录前缀，优先 frontmatter slug，兼容中文文件名回退与 basePath。

`/images/...` 统一定位到 public；相对路径也必须指向 public。微信只转换实际引用的 SVG，避免覆盖同名 PNG；图片缺失明确报错。封面优先 cover，再使用 heroImage。预览和发布共用准备后的图片文件，预览以标准 file URL 引用，不再按 /Users、/home 猜测路径。

### 7. 启动脚本结束进程的范围过大

`scripts/cli.sh` 已移除 pkill、kill -9 和按端口终止进程的逻辑。`scripts/server-status.cjs` 同时核对监听进程的工作目录与命令：当前项目对应服务直接复用，其他服务占用或无法确认时明确退出，不发送终止信号。开发服务还核对 next dev，避免误用 next start。

已实际运行 cli.sh dev，确认复用当前项目服务；回归测试中的无关 TCP 服务被拒绝后仍正常响应。

### 8. 规范全局复查的遗留问题

- Git 忽略规则原先也排除了公开的技能参考目录，新增专项说明会漏提交；现仅为规范技能下的参考目录设置例外，其他私有参考目录保持忽略
- 写作技能原先无条件要求读取 SVG 技能、通读全文，与局部错字修订的验收范围不一致；现按配图是否受影响和任务范围触发，审阅入口同步限定
- SVG 的基础校验和几何检查使用不同 viewBox 解析方式，单引号或逗号分隔写法会误报缺失或跳过几何检查；现复用 XML 解析和相同校验，新增回归覆盖
- 微信 CLI 帮助遗漏 --serve 与 --no-open；已补齐 CLI、脚本用法及文档说明

复查覆盖 12 份规范与说明文件、6 个技能入口和相关工具，11 个本地 Markdown 链接有效；12 项 SVG 回归通过，7 张目标文章 SVG 静态审计无错误或提醒。公开技能参考可纳入 Git，根目录及其他目录的私有参考资料仍被忽略。本轮未修改文章或图片，也未扩展为全站内容、图意或浏览器验收。
